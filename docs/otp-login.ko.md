# 이메일 OTP 로그인

학생은 등록된 이메일을 입력하고, 메일로 받은 6자리 번호를 입력하면 본인 숙제와 점수만 볼 수 있습니다. Google 계정이나 Google Cloud Test users 등록이 필요하지 않습니다. 기존 Google 로그인도 선택적으로 유지됩니다.

## 기존 사이트 업데이트 (한 번)

1. GitHub에서 최신 코드를 Pull 합니다.
2. `/google-sheets-setup`의 최신 코드를 기존 Apps Script Code.gs에 붙여넣고 저장합니다.
3. `setup`을 실행하고 **이메일 발송 권한**을 승인합니다. 기존 시트·토큰·학생 기록을 유지합니다.
4. Deploy → Manage deployments → 연필 → New version → Deploy로 기존 배포를 갱신합니다. 실행 사용자 Me, 접근 Anyone을 유지합니다.
5. 기존 `.env.local`의 `ACSL_SHEETS_WEBHOOK_URL`, `ACSL_SHEETS_TOKEN`, `AUTH_URL`, `AUTH_SECRET`을 사용합니다. OTP에는 Google OAuth ID/secret이 필수가 아닙니다. 파일을 바꿨다면 서버를 재시작합니다.
6. `/login`에서 등록된 **본인 이메일**로 요청한 후 받은 번호로 로그인하고 본인 과제만 보이는지 확인합니다. 실제 학생 메일을 테스트용으로 무단 발송하지 마세요.

Apps Script 배포 소유자 계정이 MailApp으로 인증번호 메일을 보냅니다. 외부 SMTP 가입이나 별도 결제 설정은 필요하지 않지만 Google의 일일 발송 제한이 적용됩니다. 이 앱은 하루 80회, 주소당 시간당 5회, 1분 간격 재발송으로 추가 제한하며 Google의 남은 쿼터도 확인합니다. 규모가 커지면 전용 이메일 발송 서비스로 전환해야 합니다. 학생 등록은 메일을 발송하지 않습니다.

## 동작과 보안

- 인증번호는 서버의 암호학적 난수로 생성하고 10분 후 만료됩니다.
- 번호 원문을 브라우저 응답이나 시트에 반환하지 않습니다. Script Properties에는 AUTH_SECRET으로 계산한 HMAC과 요청 ID, 만료 시각, 시도 횟수만 보관합니다.
- 성공하면 잠금 안에서 코드를 즉시 소비합니다. 재사용, 다른 이메일의 번호, 5회 이상 오입력은 거절됩니다.
- 등록 여부·비활성 여부·재발송 제한 여부와 무관하게 요청 화면은 동일한 안내를 보여줍니다. 미등록/비활성 주소에는 메일을 보내지 않습니다.
- 관리자가 비활성화한 계정은 받은 번호가 있어도 로그인할 수 없으며 기존 로그인도 다음 데이터 요청부터 차단됩니다.
- 학생은 자기 이메일과 연결된 학생 ID의 기록만 봅니다. Division을 바꾸면 해당 디비전의 과제가 표시됩니다.
- 메일이 안 오면 스팸함, 실제 등록 이메일, 1분 재발송 간격, Apps Script의 이메일 발송 권한·배포 버전·남은 발송량을 확인하세요.

## 관리자가 서버에서 명단 등록

이 명령은 기존 Google Sheets 서버 토큰을 사용할 수 있는 신뢰된 환경에서만 실행합니다. 실제 명단 파일은 Git 저장소 밖에 보관하고 공개 배포에 포함하지 마세요.

```sh
node --experimental-strip-types scripts/register-students.mjs /private/roster.json
```

파일 형식: `[{"name":"Example Student","email":"student@example.com","grade":"9","division":"Junior"}]`

관리자 계정 권한을 확인한 뒤 같은 이메일이 있으면 해당 학생의 이름·학년·디비전을 갱신하고 활성화합니다. 없으면 새로 등록합니다. 마지막에 전체 명단을 다시 읽어 값과 중복 여부를 확인합니다. 실패하면 성공을 주장하지 않습니다. 재실행은 같은 이메일을 중복 생성하지 않습니다. Google Sheets 직접 연결이 없는 환경에서는 실제 등록을 실행할 수 없습니다.

학생들이 집에서 로그인하려면 공개 HTTPS 배포 주소가 별도로 필요합니다. localhost는 실행 중인 컴퓨터 전용입니다.
